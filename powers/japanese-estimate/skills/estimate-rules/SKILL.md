# 日本の見積書作成ルール

日本の商習慣に沿った見積書を作成・実装するための知識をまとめる。

## 1. 見積書の一般的な記載項目

見積書には以下の項目を記載するのが一般的である。

### ヘッダー（書類情報）

| 項目 | 説明 |
| --- | --- |
| タイトル | 「御見積書」「見積書」など |
| 宛先 | 顧客の会社名。「○○株式会社 御中」の形式で記載する |
| 発行日 | 見積書を発行した日付 |
| 見積番号 | 社内で一意に管理するための番号 |
| 有効期限 | 見積内容が有効な期限（例: 発行日から30日） |
| 件名 | 見積対象の案件名 |
| 発行者情報 | 自社の社名・住所・電話番号・担当者名・メール・登録番号 |

### 明細（品目）

| 列 | 説明 |
| --- | --- |
| 品名 | 作業内容・商品名 |
| 数量 | 数量（人日・個・式など） |
| 単価 | 1単位あたりの価格 |
| 金額 | 数量 × 単価 |

### 金額サマリー

| 項目 | 計算 |
| --- | --- |
| 小計 (Subtotal) | 全明細の金額の合計（税抜） |
| 消費税 (Tax) | 小計 × 税率（標準10%、軽減8%） |
| 合計 (Total) | 小計 + 消費税（税込） |

税込の総額は見積書上部に「お見積金額」として目立つ形で記載すると親切である。

## 2. 消費税の計算と端数処理

消費税額は「課税対象額 × 税率」で算出するが、1円未満の端数が発生する。端数処理の方法は事業者が選択でき、**どの方法を採用したか社内で統一する**ことが重要である。

### 端数処理の3方式

| 方式 | 説明 | 例: 税額 123.4円 | 例: 税額 123.6円 |
| --- | --- | --- | --- |
| 切り捨て (floor) | 1円未満を切り捨てる。顧客に有利 | 123円 | 123円 |
| 四捨五入 (round) | 0.5以上を切り上げ、未満を切り捨て | 123円 | 124円 |
| 切り上げ (ceil) | 1円未満を切り上げる。事業者に有利 | 124円 | 124円 |

### 実務上の指針

- **消費税額**: 多くの事業者は「切り捨て」を採用する（顧客に不利にならないため）。
- **明細行の金額（数量 × 単価）**: 小数が出る場合は円未満を切り捨てるのが一般的。
- 税率は標準税率 10%、軽減税率（飲食料品等）8% がある。システムでは税率を設定可能にしておくとよい。
- 「税抜金額の合計に対して1回だけ課税する（総額方式）」のか「明細ごとに課税する（明細方式）」のかで最終額が変わるため、どちらかに統一する。インボイス制度では、1つの適格請求書につき税率ごとに1回の端数処理が原則。

### 計算順序の例（総額方式・切り捨て）

```
小計     = Σ(各明細の金額)              // 各明細は floor(数量 × 単価)
消費税額 = floor(小計 × 0.10)           // 1円未満切り捨て
合計     = 小計 + 消費税額
```

## 3. インボイス制度の登録番号

適格請求書（インボイス）には、発行事業者の**登録番号**を記載する必要がある。

### 登録番号の書式

- 形式: **`T` + 13桁の数字**（例: `T1234567890123`）
- 先頭は必ず半角大文字の `T`。
- 法人の場合、13桁は原則として法人番号と一致する。
- 個人事業主の場合は法人番号を持たないため、新たに13桁の番号が割り当てられる。

### バリデーションの考え方

```
^T\d{13}$   // T のあとに数字がちょうど13桁
```

見積書・請求書のテンプレートでは、自社の登録番号を発行者情報の一部として表示する。設定ファイルから読み込む場合は、サンプル値（例: `T0000000000000`）を用意し、実際の番号はリポジトリに含めない運用が望ましい。

## 4. 金額計算で浮動小数点誤差を避ける

JavaScript 等の浮動小数点数（IEEE 754）では、小数の乗算で誤差が発生する。見積書では1円のズレも許されないため、**整数化してから計算する**。

### 問題の例

```js
0.29 * 50000          // => 14499.999999999998（本来は 14500）
Math.floor(0.29 * 50000)  // => 14499 （1円下振れ）
1.005 * 100           // => 100.49999999999999（本来は 100.5）
Math.round(1.005 * 100) / 100  // => 1.00 （切り下がる）
```

### 回避方法

数量や工数が「小数第N位まで」と決まっている場合、**その桁数ぶん整数化してから計算する**。

```js
// 金額 = floor(数量 × 単価)。数量は小数第2位までとする。
function computeLineAmount(quantity, unitPrice) {
  const q100 = Math.round(quantity * 100); // 小数第2位までを整数化
  return Math.floor((q100 * unitPrice) / 100);
}

// 小数第2位への四捨五入。相対誤差(EPSILON)で境界を補正する。
function round2(value) {
  const scaled = value * 100;
  const corrected = Math.round(scaled + Math.sign(scaled) * Number.EPSILON * scaled);
  return corrected / 100;
}
```

### 設計上の指針

- 金額・工数の計算は副作用のない**純粋関数**として実装し、UI から分離する。
- 乗算・除算のあとは必ず所定の端数処理（`Math.floor` / `Math.round` / `Math.ceil`）を適用してから次の計算に渡す。
- 中間値を文字列に変換して処理する回避策は使わず、整数化で扱う。
- 計算ロジックには境界値（0・小数・上限値）と端数処理を確認する単体テストを必ず書く。より堅牢にするならプロパティベーステスト（例: fast-check）で「期待値を独立に算出して比較する」ことで、実装と同じ式で検証してしまう罠を避ける。
